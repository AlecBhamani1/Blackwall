# Blackwall 0.1.5

This planned development release batches the work on `partial` after 0.1.4 in the
[v0.1.5 milestone](https://github.com/AlecBhamani1/Blackwall/milestone/2).
[Issue #59](https://github.com/AlecBhamani1/Blackwall/issues/59) tracks preparation,
production approval, publication verification, and the main-to-partial history sync.
Preparing these notes does not approve publication or advance the stable updater feed.

## Changes

  context budgeting, `/context`, and `/compact`. Original transcripts remain available and
  restored checkpoints never restore historical approvals

## Downloads

- macOS: `aarch64.dmg` for Apple Silicon or `x64.dmg` for Intel Macs.
- Windows: `x64-setup.exe`.
- Linux: `amd64.AppImage`/`amd64.deb` for x86-64 or `aarch64.AppImage`/`arm64.deb` for ARM64.

After an approved promotion, installers and signed updater bundles will be available on the
[v0.1.5 release page](https://github.com/AlecBhamani1/Blackwall/releases/tag/v0.1.5).
The compatibility feed advances only after all platform artifacts pass publication verification.
Linux credentials require a running Secret Service; there is no plaintext fallback. The CLI is
built separately from desktop installers; the one-line development installer follows `partial`.
For version-pinned CLI installation and configuration, see the
[runtime guide](https://github.com/AlecBhamani1/Blackwall/blob/v0.1.5/docs/RUNTIME_GUIDE.md).

Local preparation checks: `npm run verify` passed type checking with zero errors/warnings,

Applicable native evidence from this batch includes real macOS Seatbelt filesystem, network,
descendant-process, cancellation, and backend-failure tests in
[#117](https://github.com/AlecBhamani1/Blackwall/pull/117), and macOS login-Keychain MCP-secret

Skill-import CLI checks in [#120](https://github.com/AlecBhamani1/Blackwall/pull/120) exercised
all nine pinned downloads and scan blocking; skill and MCP desktop screenshots used mocked
desktop backends. These results are bounded to their recorded changes, not a fresh complete
packaged-app acceptance run. Earlier pairing, lock, attachment/export, storage recovery, and
platform credential evidence remains in
[NATIVE_ACCEPTANCE.md](https://github.com/AlecBhamani1/Blackwall/blob/v0.1.5/docs/NATIVE_ACCEPTANCE.md)
and the [0.1.4 notes](https://github.com/AlecBhamani1/Blackwall/blob/v0.1.4/docs/releases/0.1.4.md).

The 0.1.4 distribution limits remain open: physical-device pairing across networks and operating
systems, sleep/wake and network changes, clean-machine installation and actual updater installation
on Windows/Linux, signed macOS upgrades and login-Keychain transitions, remaining keyboard-only
flows, lock/pairing credential mutation boundaries, broader provider/attachment coverage,
hosted-relay operations, and private beta feedback. No new evidence closes these gates.
No Apple Developer ID signing/notarization or Windows code signing is established. Updater
signatures authenticate updates; they do not remove Gatekeeper or SmartScreen warnings.
Restricted shell/command tools are unavailable on Windows/Linux unless the owner explicitly
selects unsandboxed execution. Some macOS programs requiring `posix_spawn` or home-directory
runtimes/caches can also fail under restricted profiles.

Dependency-policy exceptions remain for Linux GTK 3's `glib::VariantStrIter`
(`RUSTSEC-2024-0429`, affected API unused by the reviewed adapters), and updater-transitive zip 4
(`RUSTSEC-2026-0367`, `RUSTSEC-2026-0368`, `RUSTSEC-2026-0369`). The updater verifies archive
signatures before extraction; this mitigation does not fix zip upstream. See
[deny.toml](https://github.com/AlecBhamani1/Blackwall/blob/v0.1.5/deny.toml) and
[#121](https://github.com/AlecBhamani1/Blackwall/pull/121).

This batch upgrades the shared SQLite schema from version 2 to 4 for reviewed memories and
message search. **Back up the application data before first launch: 0.1.4 refuses the upgraded
database.** Stable and Beta share data; switching the update channel back to 0.1.4 does not
reverse this migration. Returning to 0.1.4 requires restoring a pre-upgrade backup, losing later
changes. Existing credential service names and data paths are retained. Recover a bad release
with a higher patch version; published assets and tags remain immutable, following
[UPDATES.md](https://github.com/AlecBhamani1/Blackwall/blob/v0.1.5/docs/UPDATES.md).
