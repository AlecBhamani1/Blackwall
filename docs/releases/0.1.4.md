# Blackwall 0.1.4

This development release promotes the completed [v0.1.4 milestone](https://github.com/AlecBhamani1/Blackwall/milestone/1)
from `partial` to production. [Issue #19](https://github.com/AlecBhamani1/Blackwall/issues/19)
tracks preparation, publication verification, and the production-history sync.

## Changes

- Windows 10/11 x64 and Linux x86-64/ARM64 desktop builds, including NVIDIA DGX Spark.
  Pairing and guest links work across operating systems; credentials use each platform's system
  credential store. Windows shell tools use PowerShell with descendant-process cancellation
  ([#47](https://github.com/AlecBhamani1/Blackwall/pull/47),
  [#49](https://github.com/AlecBhamani1/Blackwall/pull/49)).
- Interactive `bw` chat and setup, saved CLI settings, slash commands, project-aware session
  resume, and graceful cancellation. The CLI is built separately from the desktop installers
  ([#58](https://github.com/AlecBhamani1/Blackwall/pull/58)).
- Stable/Beta update channels with a saved preference and an explicit return from beta to stable
  ([#46](https://github.com/AlecBhamani1/Blackwall/pull/46)).
- A project file browser in Agent mode with bounded workspace searches and text previews
  ([#42](https://github.com/AlecBhamani1/Blackwall/pull/42)).
- LaTeX rendering with offline fonts, screenshot/file drops throughout the conversation, `@`
  file references, and copy buttons on individual code blocks
  ([#41](https://github.com/AlecBhamani1/Blackwall/pull/41),
  [#40](https://github.com/AlecBhamani1/Blackwall/pull/40),
  [#16](https://github.com/AlecBhamani1/Blackwall/pull/16)).
- Separate Chat and Agent histories; conversation mode and project lock after the first message
  ([#45](https://github.com/AlecBhamani1/Blackwall/pull/45)).
- Closing the macOS window keeps Blackwall and active work running; reopening from the Dock
  restores the window, while Quit and Cmd+Q still exit
  ([#48](https://github.com/AlecBhamani1/Blackwall/pull/48)).
- Checked production promotions, version milestones, a reviewed development merge queue,
  cross-platform CI, and dependency maintenance. Rust dependency migrations preserve stored
  hashes; Vitest and coverage advance together to version 5; TypeScript stays on version 6
  ([#18](https://github.com/AlecBhamani1/Blackwall/pull/18),
  [#35](https://github.com/AlecBhamani1/Blackwall/pull/35),
  [#37](https://github.com/AlecBhamani1/Blackwall/pull/37),
  [#25](https://github.com/AlecBhamani1/Blackwall/pull/25),
  [#26](https://github.com/AlecBhamani1/Blackwall/pull/26),
  [#24](https://github.com/AlecBhamani1/Blackwall/pull/24)).

## Downloads

- macOS: `aarch64.dmg` for Apple Silicon or `x64.dmg` for Intel Macs.
- Windows: `x64-setup.exe`.
- Linux: `amd64.AppImage`/`amd64.deb` for x86-64 or `aarch64.AppImage`/`arm64.deb` for ARM64.
Existing installations continue to receive update information through the original feed.
Installers and signed updater artifacts are published on the
[v0.1.4 release page](https://github.com/AlecBhamani1/Blackwall/releases/tag/v0.1.4).
Linux credential storage requires a running Secret Service; there is no plaintext fallback.
For CLI installation and configuration, see the [runtime guide](../RUNTIME_GUIDE.md).

## Acceptance status

The batch's source before release preparation is `7b999c55004f81cd3f6f6333332973c237ae9d5b`.
Its [integration CI](https://github.com/AlecBhamani1/Blackwall/actions/runs/36824293376)
passed Rust formatting, Clippy and workspace tests on macOS/Linux/Windows, UI checks and 147
tests, production UI build, dependency policy, relay-container acceptance, and 60 release/repository
tests. The [beta publication](https://github.com/AlecBhamani1/Blackwall/actions/runs/36824855076)
built all five desktop targets and verified their installer/updater assets before publishing
`v0.1.4-beta.5`. Fresh preparation/promotion CI and all five desktop promotion builds must pass
before the production merge; issue #19 records those runs and publication evidence.

Applicable recorded native evidence includes the isolated packaged macOS window-close/reopen/quit
checks in [#48](https://github.com/AlecBhamani1/Blackwall/pull/48), the isolated live remote-model
CLI smoke test in [#58](https://github.com/AlecBhamani1/Blackwall/pull/58), and Linux ARM64
Secret Service round-trip, missing-keyring recovery, packaging, and startup under Xvfb in
[#47](https://github.com/AlecBhamani1/Blackwall/pull/47). Browser checks of math rendering,
file browsing, attachments, and update-channel layouts used mocked desktop data. Earlier
same-Mac pairing, lock, attachment/export, storage recovery, and Keychain evidence and their
specific limits remain in [NATIVE_ACCEPTANCE.md](../NATIVE_ACCEPTANCE.md). These are recorded
results from their respective changes, not a new complete native acceptance run for this release.

Remaining limitations: physical-device pairing across networks and operating systems, sleep/wake
and network changes, clean-machine installation and actual updater installation on Windows/Linux,
signed macOS upgrades and login-Keychain transitions, remaining keyboard-only flows, lock/pairing
credential mutation boundaries, broader provider/attachment coverage, hosted-relay operations,
and private beta feedback. No Apple Developer ID signing/notarization or Windows code signing
is established. Updater signatures authenticate updates and do not remove Gatekeeper or
SmartScreen warnings. Publication of this development release does not declare those public
distribution acceptance gates complete.

The Linux GTK 3 dependency stack retains the medium-severity `glib::VariantStrIter` advisory
[GHSA-wrw7-89jp-8q8g](https://github.com/advisories/GHSA-wrw7-89jp-8q8g)
(`RUSTSEC-2024-0429`). [deny.toml](../../deny.toml) records the dependency-policy exception;
the review in #47 found the affected API unused by Blackwall and its Tauri/GTK adapters.
The upstream dependency remains affected and the repository alert remains open.

No database schema migration is introduced by this batch. Existing macOS credential service names
and data paths are retained. Stable and Beta share application data; returning to stable requires
an explicit user action. Future incompatible storage changes must account for that return path.
Published version assets and tags remain immutable; recover a bad release with a higher patch
version, following [UPDATES.md](../UPDATES.md).
